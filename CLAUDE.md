# DLSAuto — правила для Claude Code

Перед любой задачей прочитай `docs/DEV_CONTEXT.md` — это источник правды по разработке. Продукт и дизайн — `docs/PROJECT_CONTEXT.md`, правила визуала — `docs/DESIGN_RULES.md`. Промпт текущего этапа — в `docs/stages/`.

## Всегда

- Язык: UI — украинский (ru — второй язык через `/ru`), код и коммиты — английский, общение — русский.
- Дизайн-система раньше страниц: токены → примитивы → составные → `/ui` → страницы. Новый стиль на странице — не писать, вернуться в компоненты.
- Унификация, не редизайн: значения (размер, отступ, радиус, цвет) можно свести к канону; структуру, состав, порядок, раскладку, тексты — не менять. Сомневаешься — спроси.
- Ничего не выдумывать: категории, модели, цифры, названия — только из `docs/`; остальное — плейсхолдер с пометкой.
- Расширение модели данных сверх `DEV_CONTEXT.md §4` — только с согласованием и сразу с правкой §4 в том же коммите.
- Server Components по умолчанию; анимации — только transform/opacity + `prefers-reduced-motion`.
- Внешние сервисы — только через `src/integrations/<name>`; все операции синхронизации идемпотентны; недоступность KeyCRM не ломает заказ.
- Секреты — только в env; `.env.example` актуален.

## Процесс

- Работа ведётся прямо в `stage`. `main` — релизная ветка, обновляется только мержем из `stage` по команде владельца. Фича-веток нет.
- Conventional Commits. TypeScript strict, без `any` без комментария.
- Новая зависимость — строка в README с причиной.
- В конце задачи — отчёт: сделано / не сделано и почему / что проверить руками.
- В конце этапа: отчёт в `docs/stages/`, обновить `docs/ROADMAP.md`; новое архитектурное решение — ADR в `docs/decisions/`.
- Задача противоречит `docs/` — спросить, прежде чем нарушать.

## Известные грабли — не повторять

Каждый пункт — реальная ошибка из этого проекта. Поймали новую — добавь строку сюда в том же коммите, что и исправление.

- Сервисы (Postgres, Redis и т. п.) — только через docker compose. Никаких нативных установок в devcontainer, даже «временно для проверки». Если Docker недоступен — остановись и скажи, не обходи.
- Инструменты в devcontainer (git-lfs, gh, corepack) — только через features в devcontainer.json. Поставленное руками исчезает при пересборке.
- Цвета и типографику не «сводить к ближайшей ступени» — шкалы есть только у размеров, отступов, радиусов, высот контролов. Цвет — точное значение из экспорта, близкие оттенки — разные токены.
- Чистый #FFFFFF не удалять, если он есть в экспорте.
- Поля модели данных — строго по DEV_CONTEXT §4. Нужно новое поле — спроси; добавил — правь §4 в том же коммите.
- Редакционные тексты (подписи, описания, условия) — в Payload, не в коде. В коде — только UI-строки словаря i18n.
- Не выдумывать данные: категории, модели, цифры, названия деталей — только из docs/. Нет данных — плейсхолдер с пометкой и запись в открытые вопросы.
- Зависимости — только с согласования, со строкой-обоснованием в README.
- Запиненные версии (pnpm, Next, Payload, Node) не обновлять по подсказкам из консоли. Обновление версий — отдельная задача по команде.
- Ветки: работа в stage, фича-веток нет. main — только мерж из stage по команде владельца.
- Хуки (husky, lint-staged) не обходить через --no-verify без явного разрешения.
- Падающие проверки не «чинить» ослаблением: eslint-disable, test.skip, расширение allow-листов, смягчение CI — только с согласования.
- Структуру дизайна не менять: состав, порядок, раскладку, тексты. Унификация — только значения, в пределах 2px.
- Разметка: никаких псевдоэлементов для декора, absolute для раскладки, системных шрифтовых стеков вместо макетного шрифта, текста, разбитого на span.
- Миграции Payload запускаются из worker-образа одноразовым сервисом migrate; в standalone web-образе CLI нет.
- .env и секреты не коммитить; .claude/settings.local.json и AGENTS.md — в .gitignore, .claude/settings.json — в репо.
- Утверждённые страницы («Контакти», хедер, футер и далее по этапам) не менять без задачи; любая правка в них — со сверкой скриншотами до/после.
- Не делать молча работу «сверх задачи» (рефакторинг соседнего кода, переименования) — это отдельный вопрос.
- Заблокированная команда (сеть, пуш, sudo) — не обход, а сообщение владельцу с готовой командой.
