## Метод и оговорки

- Данные: `export-products-*.xlsx` (название, цена, наличие, группа, «Код запчастини», MPN, Код_товару), `DLSAuto_prom_rozmitka.xlsx` (категория/тип/расположение, join по `Prom ID` = `Унікальний_ідентифікатор`), `DLSAuto_dovidnyk_typiv.xlsx` (правила сторон). Парсер xlsx — собственный (zip+XML), без новых зависимостей.
- Каталог: 1407 товаров, **в наличии 1271** (`+` 1219 + `!` 52), с моделью 1309, c OEM-токенами 1356.
- **Модель = группа Prom**; категорийные группы (Диски и резина, Мосты,Редукторы, АКПП/МКПП, Двигуни, Корневая группа) → без модели. Донора в данных нет → «Ще з цього авто» = фолбэк по модели.
- OEM-токены извлекались из «Код запчастини» + MPN + Код_товару (нормализация: upper, только буквы/цифры, длина ≥5 и есть цифра).
- **Решения Р25, Р35, Р36, Р37, Р41 в репозитории отсутствуют** (в `CATALOG_PLAN_NEW.md` есть только Р1–Р16; из нужных — лишь Р10). Правила реализованы **буквально по формулировкам из задания**: альтернативи = OEM → тип+совместимое расположение (матрица Р10)+модель, широкие типы (Р35) → только по OEM, до 6; boughtTogether — по моему черновику связей типов с условием стороны (Р37), донор→модель, до 3; «Ще на цю модель» — фолбэк по модели. Список «широких типов» (Р35) и таблицы связей в репозитории нет — я составил рабочие версии и привожу их ниже; при появлении реальных Р35/Р37 сверить.

## 3. Проблемы и масштаб (по всему каталогу)

### A. OEM-подбор по неуникальному коду → кросс-тип (ПРИЧИНА В ДАННЫХ, усилена правилом)
«Код запчастини»/Код_товару у клиента часто не уникальный номер детали, а **общий код группы/листинга или код двигателя**, записанный в десятки разнотипных карточек.
- **109 OEM-токенов встречаются у ≥2 разных типов** деталей; их несут **332 товара (24% каталога)**.
- Прогон альтернатив по всем 1271 в наличии: из **727 товаров с альтернативами 283 (39%) получают ≥1 кросс-тип** (дверь как альтернатива фаре); **у 134 товаров ВСЕ альтернативы кросс-тип** (чистая нелепица).
- Источник не лечится отбрасыванием Код_товару: Код_товару даёт 53 «мусорных» токена, а **«Код запчастини» сам по себе — 88** (коды двигателей `YD25DDTi`, платформенные коды пишут в название кузова/кабины). Это данные клиента, не только правило.

### B. Слишком широкие типы → внутри типа смешиваются разные детали (ПРИЧИНА В ТИПАХ+ПРАВИЛЕ)
- **Важіль**: верхній и нижній рычаг — один тип и одно расположение → взаимные «альтернативы». Моделей с одновременно верх+низ → **18 товаров** в наличии.
- **Кардан** (правило `none`): передний и задний кардан — разные детали, но position не проверяется → смешиваются. **16 товаров**. Міст у зборі — **2**.
- **Радіатор охолодження**: 27 в наличии, из них **6 названы «ЕГР»** (радиатор EGR ≠ радиатор охлаждения) — пойдут альтернативой к основному радиатору. (Это та же первопричина B5 прошлых ревью; в нашей неперегенерированной разметке не исправлено.)
- Итого «широкие типы» затрагивают ≈ **40+ товаров**. Для wide-типа Помпа/термостат правило Р35 (только OEM) сработало верно — но список wide-типов должен включать и механические катч-оллы.

### C. Товары без модели (категорийные группы) → пустые блоки (ПРИЧИНА В ДАННЫХ)
- **98 товаров** без модели: Диски и резина 39, Мосты,Редукторы 24, АКПП/МКПП 17, Двигуни 11, Корневая группа 7.
- У них нет ни альтернатив по модели, ни boughtTogether, ни «ще на цю модель» (товар 10 — диски: всё пусто). При этом у многих есть «Сумісність з моделлю» в выгрузке — модель теряется только потому, что берётся из группы.

### D. OEM-first ставит нелепицу ВЫШЕ правды
Поскольку шаг OEM идёт первым, а сортировка потом по цене, кросс-тип двери/бамперы вытесняют реальные одноимённые альтернативы вниз или за лимит 6 (товары 1, 2, 9) — даже когда корректная альтернатива существует.

### E. boughtTogether «opposite» учитывает только бік, не ось/под-тип
Важіль «верхній лівий» → «opposite» выдал «нижній правий» (надо «верхній правий»). Для парных типов с под-вариантами условие стороны неполно.

### Что работает хорошо (не ломать)
- **Модель по группе** — корректно; твины объединены (Navara/Pathfinder, Ranger/BT-50) — альтернативы и комплекты правильно тянутся по обоим.
- **З цим купують по relatedTypes** — осмысленно (двигун→турбіна/ПНВТ/форсунка; помпа→радіатор/вентилятор; фара→фара іншої сторони).
- **Матрица Р10** — для дверей/фар работает (задня ліва ↔ задня права как opposite; пара совместима с обеими).
- **Wide→OEM-only (Р35)** — для Помпи дал единственную верную альтернативу.
