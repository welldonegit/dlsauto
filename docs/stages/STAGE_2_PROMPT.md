# Этап 2 — модель данных, админка, seed

Прочитай docs/DEV_CONTEXT.md (§4–6, §5 бизнес-правила), docs/PROJECT_CONTEXT.md (§1, §3–5), docs/stages/STAGE_1_REPORT.md. Хедер, футер и «Контакти» утверждены — это эталон качества разметки для всего дальнейшего.

Результат этапа — админка, в которой клиент может завести марку, модель, категорию, товар с фото и заполнить контент страниц; фронтенд получает данные через типизированный слой. Проверяю я руками: завожу товар в админке и вижу его на странице «Контакти»? — нет; вижу, что данные страницы «Контакти» (телефоны, пункты, график) теперь приходят из админки.

Остановка одна — в конце. По дороге вопросы — только на развилках, пакетом.

## 1. Коллекции Payload — по docs/DEV_CONTEXT.md §4

brands, models, categories, products, pickup-points, orders, leads, reviews, pages, banners, media, users; глобал settings. Поля — строго по §4, ничего не добавлять и не убирать без вопроса. Локализация uk/ru — по списку в §4; слаги общие.

Правила:
- `sku` уникален, обязателен; `oem[]` хранится как введено + нормализованная копия (нижний регистр, без пробелов, дефисов, точек) в отдельном поле для поиска.
- `status` товара: `in_stock` | `sold` | `hidden`; при переходе в `sold` — `soldAt`. Проданные не исчезают.
- Вычисляемые поля не хранятся руками: `isNew` (createdAt < 30 дней или `pinnedNew`), `partsCount` у моделей и категорий (товары `in_stock`), `fromSameCar` — запросом по model. Где нужна скорость — кэшированный счётчик с пересчётом хуком.
- Порядок: `sortOrder` у brands, models, categories, products внутри категории; в админке — drag-and-drop (Payload `orderable`).
- Доступ: `admin` — всё; `manager` — товары, заказы (чтение), заявки, отзывы, баннеры; настройки и пользователи — только admin.
- Заказы в админке — только чтение + ссылка на KeyCRM (поле `keycrmId` → URL из settings).
- Валидации: цена > 0, фото ≥ 1 для `in_stock`, slug из name с транслитерацией uk→latin, уникальность slug в коллекции.

## 2. Медиа

Коллекция media с sharp-вариантами из §4 (thumb 400, card 800, gallery 1600, WebP + оригинал), focal point, alt обязателен (локализуемый). Хранение — `/data/media` (volume в compose), в dev — `./media`. Загрузка нескольких файлов разом в товар, порядок перетаскиванием, первое — главное, видео (mp4) последним.

## 3. Страницы блоками

Коллекция pages с `layout: blocks[]`. Типы блоков — по docs/PROJECT_CONTEXT.md §4–5, по одному типу на каждый блок главной и «Про компанію»: hero (A/B), stats, categories (A/B), modelsPicker, newArrivals (параметры: лимит 15, автозаполнение), services, pickups, suvs, videoCheck, faq, reviews, benefits, whatElseWeDo, aboutHero, whyDisassembly, partPath, team, ctaText, richText, contacts. Каждый блок — свои поля с украинскими лейблами и подсказками для клиента; пустой блок (нет контента) не рендерится. Для блоков с автонаполнением (новинки, пикапы, внедорожники) — поля «лимит» и «закрепить вручную[]».

Фронтенд-рендер блоков в этом этапе — **только каркас**: `BlockRenderer` с маппингом тип → компонент и компонентом-заглушкой, который выводит имя блока. Реальная вёрстка блоков — этап 3.

## 4. Settings и Контакти на реальных данных

Глобал settings по §4 (телефоны, мессенджеры, email, соцсети, рейтинг Prom, ссылки на маркетплейсы, мин. заказ, время отправки, условия предоплаты, «Приймаємо», реквизиты ФОП, season с датами, KeyCRM base URL). Страница «Контакти», хедер и футер переводятся с заглушек на settings и pickup-points — без изменения вёрстки. Статус «Зараз відкрито» считается по графику пункта.

## 5. Слой данных для фронтенда

`src/lib/data/` — типизированные функции (`getProduct(slug)`, `getProductsByModel`, `getCategoryTree`, `getPage(slug)`, `getSettings()` …) поверх Payload Local API. Кэширование через `unstable_cache`/tags с инвалидацией хуками Payload (`afterChange` → `revalidateTag`). Никаких прямых вызовов Payload из компонентов.

Бизнес-правила в `src/lib/rules/` с unit-тестами: дата отправки «Сьогодні / Завтра / У понеділок» по Europe/Kyiv и графику; isNew; нормализация OEM; формы слова «деталь / деталі / деталей»; статус «Зараз відкрито».

## 6. Seed и импорт

- `pnpm db:seed` — реалистичные данные из docs/PROJECT_CONTEXT.md: 16 марок с логотипами из экспорта, модели с годами и близнецами, 9 категорий, два пункта выдачи, settings, страницы «Головна» / «Про компанію» / «Контакти» / «Оферта» / «Політика» / «404» с блоками, ~40 товаров с фото-заглушками из экспорта (OEM, цены, состояния, часть `sold`, часть со скидкой, часть `featured`, часть `seasonalDecor`). Идемпотентно.
- `scripts/import-prom.ts` — импорт из стандартного YML-экспорта Prom: категории → categories (маппинг-файл), товары → products в статусе `hidden` с пометкой «імпорт, перевірити», фото скачиваются в media, `promId` сохраняется, `sku` — из артикула Prom, если есть. Тексты только ru → ru-поле, uk-поле пустое с флагом `needsTranslation` (машинный перевод — позже). Повторный запуск обновляет по promId, не дублирует.

## 7. Админка — удобство для клиента

- Интерфейс на украинском: лейблы, подсказки, названия коллекций, статусы.
- Списки: товары — колонки фото, sku, название, модель, категория, цена, статус, город; фильтры по статусу, категории, марке/модели, городу, `isNew`, `featured`, `seasonalDecor`; поиск по sku/oem/названию.
- Массовые действия на выбранных товарах: статус, `seasonalDecor` вкл/выкл, `featured`, пункт выдачи.
- Дашборд админки: заглушка под этап 7 — только счётчики «в наличии / продано за 30 дней / заявки без ответа».

## 8. Критерии приёмки

- Все коллекции и settings созданы, миграции закоммичены, `pnpm db:seed` на чистой БД отрабатывает.
- В админке: создать марку → модель → категорию → товар с 3 фото → увидеть его в `getProduct`; drag-and-drop порядок работает; массовое действие на 5 товарах работает.
- «Контакти», хедер, футер — на данных из settings/pickup-points, вёрстка не изменилась (Playwright-сверка с результатом этапа 1 — 0 расхождений).
- Unit-тесты бизнес-правил зелёные; `/ui` не сломан.
- Импорт из Prom: прогнать на тестовом YML (возьми структуру из документации Prom, сделай фикстуру из 10 товаров), результат — 10 `hidden` товаров с фото.

Коммиты: коллекции → медиа → страницы и settings → слой данных и правила → seed → импорт → админка. Отчёт `docs/stages/STAGE_2_REPORT.md`, ROADMAP обновить. Зависимости — только с согласованием.
