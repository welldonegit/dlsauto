# ADR 001 — KeyCRM як хаб обліку

- **Статус:** прийнято.
- **Контекст:** продажі йдуть кількома каналами (сайт, Prom.ua, avto.pro, OLX), кожна деталь в одному екземплярі → головний ризик — подвійний продаж.
- **Рішення:** KeyCRM — майстер по наявності та замовленнях; сайт — майстер по контенту; Prom — канал, що живить KeyCRM. Зв'язка товарів по `sku`. Усі операції синхронізації ідемпотентні; недоступність KeyCRM не ламає замовлення (локальний `pending_sync`, воркер досилає).
- **Відкинуто:** власний облік залишків на сайті; пряма синхронізація кожного каналу з кожним (N×N, неконсистентно).
