# ADR 006 — Шар даних: Local API + unstable_cache + ревалідація хуками

- **Статус:** прийнято (етап 2).
- **Контекст:** фронтенд не має звертатися до Payload напряму (DEV_CONTEXT §3, §5); потрібні типізовані читання з кешем і коректною інвалідацією при правках у адмінці.
- **Рішення:** усі читання — через `src/lib/data` поверх Payload Local API (`src/lib/payload.ts`), обгорнуті в `unstable_cache` з тегами колекцій (`src/lib/data/revalidate.ts`). Запис у колекції/глобал викликає хук `afterChange`/`afterDelete` → `revalidateTag` (Next 16: другий аргумент — профіль `max`). Хуки підключаються централізовано в `payload.config` обгорткою `withRevalidate`, тому колекції лишаються чистими. Поза request-скоупом (seed/CLI) `revalidateTag` безпечно ігнорується.
- **Відкинуто:** прямі виклики Payload з компонентів; ручний кеш; `'use cache'` (новий, ще не стабільний для цього стеку).
- **Нюанс:** у dev `unstable_cache` зберігається в `.next/cache`; після зовнішнього `db:seed` потрібен `pnpm devsafe` (в проді правки йдуть у тому ж процесі й інвалідуються коректно).
